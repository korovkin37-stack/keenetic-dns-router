# Изменения

[English](CHANGELOG.md) · **Русский**

## 5.48.1
- Сервис / BGP: каждая сессия теперь отдельный чип — со светодиодом состояния, адресом соседа, его AS и состоянием прямо в строке (Established — зелёный светодиод, любое другое состояние — янтарный). Раньше все сессии выглядели одинаковыми ячейками «Session Established / Active», и узнать, какой сосед какой, можно было только в подсказке на кружке «i»; при нескольких сессиях приходилось наводить на каждую по очереди. Подсказка по-прежнему содержит полные детали, остальное в плашке не менялось.
- Сервис / ndm-хуки: у каждого событийного хука (пересборка файрвола, подъём интерфейса) появился выбор, что он обновляет при срабатывании, — всё, только цели или только списки. Маршруты применяются всегда: для этого хук и срабатывает. Выбор хранится на хук (hook_scope_<id> в таблице settings), показывается и меняется прямо в списке хуков, а диспетчер (jobStepsFor) пропускает шаги, которые область исключает. У хука BGP выбора нет: он сам стартует/останавливает bird и задач панели не ставит.

## 5.48.0
- Верхняя сетевая полоска теперь говорит, что делает: под ней появляется «пилюля» с названием идущей операции. GET берёт подпись из словаря читающих действий панели (Загрузка целей…, Проверка DPI…, Проверка дрейфа маршрутов… и т.д.), POST — текст нажатой кнопки, а вызов может передать явную подпись третьим аргументом apiFetch. Когда запросов несколько, «пилюля» показывает первый из них и счётчик (+N); у запроса без подписи остаётся «Загрузка…». Спиннер на кнопке, задержка 800 мс для чтений и всё остальное в поведении полоски не менялись — она только стала информативной. Новые строки переведены в русском языковом файле.

## 5.47.1
- Обновление панели: проверка релиза больше не упирается в память на роутере с малым лимитом PHP. Архив распаковывается в файл кусками по 64 КБ, и каждый файл сразу пишется во временную папку, а не держится в памяти целым tar: gzdecode растил буфер удвоением и просил сразу 2 МБ, поэтому при memory_limit 8M проверка умирала с «Allowed memory size of 8388608 bytes exhausted (tried to allocate 2097152 bytes)». Пик всей проверки теперь — сам код панели, около 6 МБ, и она проходит даже там, где лимит нельзя поднять на ходу.
- Обновление панели: свой лимит памяти запрос берёт из настроек (Память веб-запроса), а не из того, что случайно стоит в php.ini; контрольная сумма скачанного считается hash_file, загруженный архив декодируется из base64 кусками, а языковой файл проверяет дочерний php-cli — словарь не разбирается внутри веб-запроса.
- Настройки: новый предел «Наибольший распакованный архив» (32 МБ, 1-256) ограничивает распакованный размер обновления, чтобы повреждённый архив не забил диск.
- Обновление панели: у сообщений этого пути, у которых не было русского перевода, теперь он есть — проверка языкового файла, проверка синтаксиса PHP, чтение и запись файла из архива.
- Проверки: tests/update.php — 40 проверок. Главная гоняет всю проверку в дочернем процессе под жёстким memory_limit 8M с отключённым ini_set и требует успеха байт в байт.

## 5.47.0
- Интерфейсы: у каждого видно, включён ли NAT. Это галка Keenetic «Использовать для выхода в интернет» (свойство global): без неё туннель поднят и адрес есть, но трафик из сети через него не идёт. В карточке показан приоритет global, список считает туннели без NAT, а сама панель умеет включать и выключать NAT. Выключение на текущем шлюзе или на последнем глобальном интерфейсе требует подтверждения.
- Статические маршруты: маршрут можно изменить, а не только добавить и удалить. Правка пишет новый и снимает прежний в два шага, поэтому неудачное снятие не оставляет двойника. Меняются адрес, шлюз, интерфейс, комментарий и обе отметки.
- Статические маршруты: статус теперь говорит, чего именно ждёт. «Ждёт интерфейс» было неверно: отметка auto ждёт доступности шлюза, поэтому теперь «Ждёт шлюз», а выключенный или исчезнувший интерфейс называется отдельно. Живой шлюз не обвиняется: если им пользуется другой маршрут, причина — «Нет в таблице».
- Статические маршруты: новая кнопка «?» разбирает один маршрут по требованию — куда ядро отправляет адрес сейчас, какие живые маршруты его накрывают, поднят ли названный интерфейс и есть ли на нём NAT. В колонке интерфейса показан тот, что выбрал роутер, если в маршруте он не задан.
- Статические маршруты: отметка reject показана и её можно поставить. Проверки — как в справочнике Keenetic: только вместе с auto, только с названным интерфейсом и никогда для маршрута по умолчанию. Подпись auto стала честной: ждёт шлюз, а не интерфейс.
- Проверки: tests/round7.php — 88 проверок. Подставной http-поток держит все обращения к RCI внутри песочницы.
- Упаковка: в ZIP теперь метка времени каждого файла выводится из его содержимого, а не одна общая дата на все. С общей датой git мог не заметить правку: он считает файл неизменным, если совпали и размер, и метка времени из индекса, а правка одной строки версии размер не меняет. Именно поэтому app.php и оба README иногда не появлялись в списке изменений после копирования архива.
- Упаковка: этот архив — пересборка той же 5.47.0. В каждом текстовом файле есть однострочная пометка, поэтому каждый отличается и размером, и меткой времени, и git показывает их все после копирования архива поверх клона. LICENSE и скриншоты байт в байт совпадают с прошлой сборкой и не тронуты. README: новый раздел «Копирование релиза поверх локального клона».
- Переводы строк: добавлен .gitattributes — каждый текстовый файл хранится и выгружается с LF, независимо от core.autocrlf. Это убирает предупреждение GitHub Desktop о том, что LF превратятся в CRLF при следующей выгрузке, и защищает install.sh: с CRLF он на роутере вообще не запускается. Воркфлоу теперь отказывается собирать релиз, если в текстовом файле появился CR.

- Релиз этой версии на GitHub не собрался: воркфлоу ещё искал номер версии в index.html. Сами файлы панели в порядке - 5.46.1 это та же панель с исправленной сборкой.
- Настройки, «Таймауты и лимиты»: в настройки вынесены все таймауты и все лимиты панели - 57 величин в восьми группах («Загрузки», «Разрешение DNS», «Списки», «Задачи и роутер», «Хуки», «Проверка DPI», «Диагностика и таблицы», «Панель и безопасность»). У каждого поля видны единицы, допустимые границы и подсказка, что оно меняет; код берёт числа из одного реестра, а не из написанных в нём цифр.
- Значения по умолчанию - ровно то, как панель работала раньше, поэтому обновление ничего не меняет, пока вы не тронете поле. Значение, равное значению по умолчанию, не сохраняется: в базе лежит только то, что вы изменили сами, поэтому следующая версия сможет улучшить нетронутое значение по умолчанию, а ваши правки останутся.
- Значения проверяются при сохранении (границы, целое там, где нужно целое, и две пары, которые осмысленны только по порядку) и зажимаются в границы при чтении, поэтому вручную исправленная база не может сломать панель. Стрелка у поля, кнопка под группой и «Сбросить всё» возвращают значения по умолчанию.
- Загрузки: бюджет на соединение и на передачу, число повторов, пауза перед ними и их общий потолок, порог и время зависшей передачи, наибольший файл. Это то, что нужно медленному туннелю: прежние 15/120 с теперь значения по умолчанию, а не закон.
- DNS, списки и задачи: сколько запросов идёт одновременно и сколько может длиться ответ, сколько серверов можно перечислить, сколько доменов списка разрешается, строки и текст своего списка, защита от усадки (теперь в процентах, 0 её выключает), таймауты ответа и команд роутера, ожидание блокировки базы, лимиты времени и памяти, очередь и история задач.
- Хуки, DPI и диагностика: как часто хуки ndm могут обновлять домены и списки, таймауты и параллельность проверки DPI, сколько расхождений, соединений и имён показывают диагностические таблицы, сколько тестов может идти одновременно.
- Панель и безопасность: сколько помнится вход, сколько неверных паролей блокируют адрес и на сколько, пауза после неверного пароля, окно обновления, наибольший архив обновления, кэш ответа GitHub.
- Бейдж версии в сайдбаре заполняет app.js из JS_VERSION: в index.html своего номера больше нет, поэтому страница, задержанная кэшем браузера, не может показать версию, которая не работает. Версия теперь живёт в трёх местах, и релизный workflow проверяет, что бейдж остался динамическим.
- Новая проверка tests/limits.php (86 проверок): реестр полон и каждая величина действительно используется, границы и валидация, сброс, бюджеты curl из настроек и что ни один перевод новой карточки не потерялся.
- Новая проверка tests/limits_ui.js: рисует карточку настоящим renderLimits() из app.js и настоящим реестром из app.php, по-английски и по-русски, без браузера - забытое поле или потерянный перевод валят проверку.

- Свои списки: «+ Свой список» на вкладке «Списки» принимает вставленный текст или ссылку на файл. Каждая строка распознаётся сама: домен, IP или сеть; понимаются комментарии, файлы hosts, строки adblock (`||example.com^`), v2fly (`domain:`, `full:`), `*.example.com` и ссылки. «Проверить» показывает, что найдено и какие строки пропущены и почему. Дальше свой список работает как любой другой: одна строка, объединение подсетей, защита от «пропало полсписка», домены резолвятся через ваши DNS при каждом обновлении; ссылка скачивается заново каждый раз.
- Каждое поле шлюза (цели, массовая правка, списки, свои списки, каталог, статические маршруты, мастер bird) предлагает шлюзы, которые уже используются в целях и списках, — сначала самые частые.
- Задача от роутера показывает, какие события её вызвали: «Событие роутера: поднялся Wireguard0, пересобран firewall (mangle)» в списке задач и строка «event: …» в начале журнала. События, пришедшие, пока задача ждёт в очереди, добавляются к ней. Хуки ndm теперь передают панели интерфейс и таблицу; обновление само их перезаписывает (хук с вашим текстом остаётся как есть).
- Запасной выход для целей и списков (интерфейс или шлюз). При каждом применении панель проверяет основной выход: если Keenetic говорит, что он не подключён, или не проходит проверка связи, маршруты уходят на запасной; когда основной снова работает — возвращаются. Пишутся только изменившиеся маршруты. Шлюз сопоставляется с интерфейсом по подсети, поэтому работают и цели, заданные шлюзом. Запасной выход, который тоже не работает, не используется.
- В таблице целей, пока работает резерв, основной выход зачёркнут → запасной, сверху плашка; в карточках проверок связи — с какого времени включён резерв и что куда ушло. В журнале задачи — строки «failover:».
- Массовая правка умеет задавать и убирать запасной выход; экспорт и импорт его сохраняют.
- Хук интерфейсов ndm сообщает и об отключении интерфейса; задача ставится, только если этот интерфейс — основной выход у чего-то с резервом.
- Политика везде показывается вместе с описанием: детали цели, все списки политик (цели, списки, каталог, массовая правка, тест маршрута, клиенты, BGP, импорт), таблица клиентов и соединения, проверка таблиц, проверка DPI. Описание больше не переводится («Custom VPN» местами превращалось в «Свои VPN»).
- В сообщениях о запасном выходе интерфейсы названы вместе с описанием: «Wireguard2 (amnezia, nwg2) не подключён … на запасном выходе GigabitEthernet1 (ТТК, eth3)».

## 5.41.4
- Исправлено зависание задач, запущенных из панели, с пустым журналом. Фоновый процесс писал вывод в файл с именем по владельцу app.php. Как только этот файл один раз создавал хук (от root), пользователь веб-сервера уже не мог его открыть, и оболочка вовсе не запускала задачу. Теперь имя файла берётся по пользователю, который запускает процесс.

- Задача, процесс которой так и не поднялся, больше не висит «выполняется» бесконечно: оболочка вокруг процесса отслеживается с первой секунды, а задача без процесса дольше минуты закрывается.

## 5.41.0

По клику открываются подробности по политикам и таблицам: маршруты, которых нет в роутере; маршруты, ведущие на другой интерфейс или шлюз; маршруты и ip rule, которых нет в базе. ## 5.40.2
- Применение сравнивает таблицы с тем, что в них должно быть, и пишет только разницу: недостающие маршруты и маршруты с другим шлюзом или интерфейсом. Если ничего не изменилось, ничего не пишется и root не вызывается: частые срабатывания хуков ничего не стоят, роутер не подтормаживает. В журнале задачи видно, сколько маршрутов добавлено, изменено, удалено и не тронуто.

## 5.40.1
Исправления после проверки 5.40.0.
- Правильные ip rule не трогаются; правило, которое роутер не дал добавить, показывается в задаче и в окне списка, а не прячется за «маршруты применены».

## 5.40.0
Второй раунд аудита.
- Маршруты применяются без провала: новые пишутся поверх старых, потом удаляются лишние; таблицы больше не очищаются, трафик цели не теряет маршрут ни на миг. Два вызова от root вместо десятков.
- bird4.conf проверяется `bird -p` до сохранения; конфиг, который bird не принял, не записывается. Включение лога bird больше не принимает «No syntax errors» за ошибку.
- Прогоны DPI хранятся в базе, а не в папке `dpi/` (старые переносятся сами).
- Загрузки (списки, GitHub): не больше 20 МБ, только http(s), редиректы только на https; источник списков не может указывать на сам роутер.
- Метки политик из Keenetic принимаются только как hex, прежде чем попасть в `ip rule` и хук bird.
- Не больше 100 политик (таблица списков на 100 выше таблицы политики).
- Импорт целей — одна транзакция: всё или ничего, и намного быстрее.
- Правка, удаление и обновление несуществующей цели сообщают об этом; `enabled` читается как логическое.
- Список с доменами больше 1000 сообщает, что остальные не разрешались; списки читаются построчно.
- В тесте DNS не больше 8 серверов, одновременно не больше двух тестов; curl в тесте маршрута идёт по очереди.
- Пока заменяются файлы панели, остальные запросы ждут (503), а не попадают на смесь старого и нового кода.
- Окна: Tab не выходит из окна, страница под ним не прокручивается, фокус возвращается после закрытия; крестик — кнопка.
- Окна с деталями игнорируют запоздавшие ответы на прошлый запрос.

## 5.39.0
